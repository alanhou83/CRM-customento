# CRM / CBOS 数据交换规则 v1

2026-11-20，用户确认开始实施。CRM代码仓库公开且网址不变；CRM-customento-data私有；CBOS私有且既有工作方式不变。GitHub为个人试跑的过渡存储，非正式多人数据库。

## 存储与授权

- 数据文件 `state/snapshot.json`：`schemaVersion:1`、`revision`、`updatedAt`、`stores`、`images`。`stores`沿用现有crm_*键的JSON值；稳定ID、sourceImportId和引用不重编。
- 图片文件 `images/<sha256>.webp|png|jpg`，记录id、详情和缩略图文件路径、SHA256、MIME、字节数和像素尺寸。哈希相同不重复写入。不能把Base64图片堆进业务JSON。
- 令牌默认仅在本次页面内存使用；用户主动选择“记住此设备”后独立保存到本机localStorage的crm_sync_device_token_v1，绑定指定仓库，不进入业务快照。不得写入源码、URL、备份或日志。本机持久授权不是加密保险箱，仅本人设备启用；取消授权清除本机和内存令牌，保留业务数据，完整备份恢复也清除授权。限定单一私有数据仓库Contents读写及必需Metadata读取，设置有效期。当前角色选择不等于服务器身份验证；数据仓库权限才控制访问。
- 首次远端为空时必须明确初始化，不能空数据覆盖已有浏览器。已有数据先备份，验证私有仓库后再上传。应用代码移除业务样板后不得把空白库自动上传覆盖远端。

## 合并、删除与冲突

- 按上次成功同步的基线做三方合并。无变化跳过；只有一方变化取变化值；双方相同修改合并。
- 对象按字段比较；有稳定ID的数组按记录合并；没有ID的跟进字符串仅追加去重，不自动推断跨设备删除或更正。
- 删除用显式tombstone，留原ID和删除版本。表里缺记录、空字段都不自动当删除。首次迁移不重编号；跨设备同一数字ID对应不同新记录时必须冲突处理，不能错误串联。
- 冲突保存本地/远端/基线和来源，待人工选择；一个状态只有一个生效值。不以设备时间后者获胜。每次远端写入必须校验GitHub SHA，竞争写入失败时重拉、重新合并，不能强制覆盖。
- 同步失败/断网保留本地修改；上传全部完成后才标已同步。同步过程中若本地又修改，不覆盖新修改。开启时可同步；关闭时仅尽力触发，不能保证完成。前台定时同步兜底。

## CBOS

- 询盘跟进文字与状态以CBOS为主，CRM图片归CRM；确有双方修改保留冲突。不覆盖订单、采购、生产、库存、财务。
- CBOS输出包含schemaVersion、batchId、exportedAt、source、inquiries（稳定sourceImportId/updatedAt/revision）、followups（稳定eventId/inquiryId/date/content）、backgrounds。发生时间未知保留空，不能拿导出时间替代。
- 既有导入资料先作为基线；老跟进可按来源ID+原表行创建固定事件ID，后续必须沿用。再次导出不能按新行号为原事件重新编号。
- GitHub Actions若运行于CBOS，可读本仓库；写另一个私有仓库需要单独最小权限凭据，默认GITHUB_TOKEN不会自动获得跨仓库权限。动作未配置/验证前不能宣称自动同步已启用。

## 图片

- 详情硬上限300,000字节，缩略图硬上限60,000字节（界面KB按十进制），不设最小大小、不放大小图。
- 最长边详情1600px、缩略图320px，等比例缩小，优先WebP；透明图必须保留alpha，可回退PNG，非透明图可JPEG。
- 自动降低质量/尺寸至上限内，失败明确报错，不保存超限或损坏图片；列表读缩略图，详情读详情图。现有图片不批量覆盖，迁移前保留备份。
- 只处理普通参考图；未来生产原稿另设计，不能当前冒称无损原稿管理。

## 发布边界

私有仓库基准写入并核验、两设备同步测试通过后，才从公开当前源码移除业务数据；Git历史清理需要单独具体方案，当前不强推/重写历史。公开文档也需避免留下业务明细。PWA保留HTML网络优先，不要求重装，不清除IndexedDB。

## 当前实施与执行规则（2026-11-21）

已发布：公开代码与私有业务数据分离、GitHub同步入口、可选记住设备授权、首次确认舍弃本机旧内容后接收云端、三方合并/冲突处理、完整备份及恢复、图片压缩与同步、PWA版本化资源更新。用户确认手机同步成功；不以此声称多人数据库、完整ERP或所有设备验收完成。

CBOS端结构化询盘投影、固定商机/事件ID、增量生成器及跨仓库Actions已经配置，真实首批发布成功，CRM云端快照已记录应用该批次。运行编号、客户明细及证据只记录私有项目记忆。

### 客户跟进的日常闭环

1. Codex在CBOS完成真实业务整理并更新事实主记录，同时维护机器可读投影，校验后同次提交推送。用户无需反复要求导表；投影是派生交换资料，不替代事实主记录。
2. main上的投影更新触发Actions，读取已整理字段，生成带版本的不可变增量批次并写入CRM私有数据仓库。默认GITHUB_TOKEN只读源仓库；目标写入凭据用Actions Secret保管，不进入代码、日志或文档。
3. CRM在已授权打开/前台定时/手动同步时接收批次，以固定ID更新。后台发布与设备接收是两个阶段，PWA关闭不保证实时接收。
4. 仅聊天尚未落档、只修改Markdown但漏更新投影，均不会自动传送。Codex负责补齐并核对Actions结果，失败如实报告，不能要求用户反复搬数据弥补遗漏。

覆盖询盘、客户背景与跟进，支持按规则新增商机；未覆盖全部客户主档、订单、产品、采购、生产、库存及财务。CRM参考图片仅在CRM与数据私库同步，不进入CBOS。稳定ID不重编号、事件追加去重、空值不覆盖、未知日期/金额/负责人不猜填，双方变更保留冲突。

发布器只改CBOS批次/索引/发布摘要，不直接写业务快照或图片；业务快照由CRM正常同步形成。跨仓库并发不强推、不覆盖手机新修改。GitHub为正式部署前过渡存储，后续迁移保留字段、ID及增量契约，不围绕过渡同步扩展长期业务功能。

同步时会话授权未建立就不能自动拉取；当前页面授权成功后可每3分钟前台尝试、回到前台时尝试，关闭只尽力触发。未选择记住设备时，令牌不跨刷新保留；选择记住设备后重新打开可恢复授权并尝试同步，仍受令牌有效期、网络和冲突影响。完整备份在个人设置下载，包含图片；同步前备份存独立IndexedDB `customento-sync-backups-v1`，不塞进localStorage以避免图片耗尽5MB空间。

首次连接没有基线时，空设备读取云端；已有本机记录需先确认并完整备份，再接续云端基准。有本机图片也可明确确认舍弃，校验云端并完整备份后替换，不再要求旧演示图片映射。设置的完整备份可从原“导入恢复”入口恢复；恢复前也创建备份，并停止会话自动上传，重新授权后再同步。

### 首次接收云端基准
无本机同步基线时，新空设备直接接收；已有本机记录或图片先明确确认舍弃旧内容。下载并校验云端、核对远端版本和本机未变化、保存完整本机备份后替换业务存储及图片（含移除云端不存在的旧记录/图片），不上传旧内容，保留本机授权。取消、图片下载/校验失败或版本竞争不清除旧数据。后续按既有三方合并处理，不再次全量舍弃。

### 生产管理接入（2026-11-22，v54）

`crm_production_v1`纳入SK、三方合并及完整备份；旧的`crm_prod_v5`仍是产品开发。生产只引用现有产品/SKU，领退料仍写原库存台账，采购草稿仍写原采购存储。同步和恢复执行生产关联/数量校验，拒绝跨设备重复建单、超额预留、重复采购覆盖及交接不足。数据结构、公式、操作与边界见[生产管理说明](production.md)。不注入真实工单或库存，不改变CBOS字段边界。

v56在同一schemaVersion内增补工艺/包装方案、设备、选用快照、任务重组审计及组合执行数组，旧数据缺失时归一为空。方案版本和选用/执行均用稳定ID；重组保留软归档任务及来源，不以删除记录丢弃历史。合并后拒绝方案版本碰撞、重复安排超需求、组合主记录与步骤进度或工时不一致；遇冲突保留本地供核对。新增版本不会反写既有选用快照，实际投入仍引用原库存领用。详见生产说明v56；CBOS询盘投影范围不扩大到生产数据。
