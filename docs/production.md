# 生产管理第一阶段（v54试跑版）

生产管理独立于“产品开发”，复用产品库、采购与库存。应用不内置真实物料、人员、工单或期初库存；从现有销售单建立工单，物料档案不足时回产品库补充实物SKU并启用库存。

## 操作入口

- 电脑左侧“生产管理”；手机“全部 → 生产管理”。订单详情的“生产工单”可查看关联任务或新建。
- 管理入口：新建工单、核料领料、工序配置、报工记录、进度看板、采购工作台、工序库。
- 生产员入口：选择试跑人员、查看分派任务、填写本次完成数量；支持一份小组产量和每人人时。当前角色与姓名切换仅为本地试跑界面，不构成员工身份认证。
- 工序库、模板初始为空；经验产能可留空，不用虚构速率才能开工。配置与历史用于参考，不能复制旧库存或已发生业务。

## 数据与数量口径

`crm_production_v1`（`SK.production`）存储schemaVersion=1。批次、产品任务、物料行、预留事件、投入记录、报工、工序、模板和订单改量日志均使用稳定ID。`SK.prod`仍为产品开发，不改名、不挪用。

- 工单可合并多张销售单。默认每条订单产品独立；用户确认工艺/包装一致后才按相同SKU及单位合并。保留来源订单ID、明细ID、原编号、交期与数量；同明细不能重复建立有效工单。
- 本批物料按真实SKU及库存单位聚合。清单不是另一套物料主档；不使用产品编辑表单中的静态stockQty作为生产余额。
- 实存=既有库存movements的签名数量合计。无流水且未核对时显示“未建账”。核料仅表示本批需求与账实已由经办核对，库存修正仍在原库存模块留流水。
- 理论需求与备料目标分开。可以按选中的产品量÷每单位物料理论产出数向上取整；不同产品单位不混算，损耗不假定为固定比例，备料余量由主管决定。
- 未领预留=本物料预留/释放事件净额－累计领料。预留只减少未分配可用，不扣实存；领料同时扣仓库实存并消耗预留，因此不重复扣两次。
- 机旁未用=累计领料－退料－有效实际投入。退料只退未用部分，增加原库存流水，不自动恢复预留；实际投入/损耗留独立事实，不重复扣仓库。不把理论量当实耗。
- 生产领退料在同一次库存存储写入中生成已确认出/入库单及流水，带工单、物料行、实际经办与录入人。不能在通用库存单入口作废以绕过生产关联；退料/补领和更正投入回生产入口操作。
- 待采购缺口=目标－未领预留－净已领－采购草稿覆盖－已下单待到覆盖，最低为0。可用现货先预留再安排缺口，防止重复采购；草稿不等于在途，更不增加现货。
- 采购工作台可跨工单选物料，按本次选定供应商/币种生成原采购模块中的草稿，同SKU及单位合并明细，`productionLinks`保留每个需求来源。空白单价表示待核价；没有生成银行流水或应付。
- 覆盖按采购单当前SKU/单位/数量及已确认收货计算；采购删行、减量、作废不继续沿用旧覆盖。编辑后不足的来源重新显示缺口。当前同SKU的合并收货按来源先后覆盖，现场若需要指定跨工单分配需后续设计；已入库物料仍需实际预留/领用。

## 工序与报工

基础工序与本单路线分开；路线保存独立步骤ID、版本、名称/要求快照、人员及可空的产能参考。支持新增、排序、重复同类步骤、逐款包装要求。下达前核对包材；下达后无报工可撤回，已有报工保留原版本，暂不提供带报工的路线重排。

报工记录本次增量，小组一份产量、多人各自工时，填报人与实际参与人分开。重复点击沿用同一提交ID。超过计划仍保存原数并提示；“已报”与“确认可流转”分列，后道确认不能超过上道可交接量。超产/交接异常需核对说明。不自动生成合格成品库存、发货、财务或订单完成状态。

可补充/更正工时且保留前后值；不改变产量。报工撤销留原因，后道已有交接时需先更正受影响后道。实际投入也可撤销留痕。看板按同产品/同工序累计，产能参考区分人时和机器小时；缺工时不展示虚假效率。

来源订单数量/交期发生变化不会静默重算工单。数量变更须经明确核对并保留前后来源，提示重新核料；工人仍可记录真实报工，来源未核对时暂停确认流转，避免计划变更让现场漏报；删除明细、更换SKU/单位暂不以普通改量处理。原采购、领料、报工不因改量自动消失。

## 同步、备份与保护

- 新存储键纳入正常GitHub三方合并及完整备份；旧备份缺少已发生生产领料关联时停止恢复。常规JSON备份也包含生产和库存。
- 合并校验拒绝重复销售明细工单、超额预留、超额领退/投入、重复采购覆盖、断裂的SKU/物料引用及后道交接不足，保留本机数据供核对，不靠覆盖处理。
- 同浏览器生产操作尽可能使用Web Locks串行化，写入前读取最新存储；已有编辑表单遇数据变化须重新打开，防止用旧配置覆盖同步结果。本地存储和GitHub过渡同步不等于数据库事务；多人并发正式部署仍需服务端约束。
- 库存修改不能侵占已预留数量。盘点发现实存低于预留时先在工单释放受影响预留，再在库存模块记真实盘点差异；不直接改生产余额。
- PWA v54：HTML保持网络优先，预缓存主HTML及带版本的生产JS/CSS；私有跨域/授权请求不入静态缓存。不清localStorage、IndexedDB或设备授权。

## 本阶段边界与验证

已实现基础工单→选料/历史配置→核料/预留→领退料/实际投入→采购草稿→配置/下达工序→个人/小组报工→进度的操作链。

后续试跑：正式员工账户权限、仓库点位/批次、同一次跨产品共同投入/报工、指定收货分配、返工、新旧路线版本转换、成品完工入库与销售交付分配、按设备日历排产及齐套预警。当前不宣称完整ERP已跑通。

验证入口：`node tests/production.test.cjs`、既有同步/CBOS测试、所有新JS/Service Worker/HTML内联语法与`git diff --check`。手机尺寸和离线验证使用隔离Chromium，不等于真实iOS验收；真实数据只可在仓库外隔离预览，不写入公开测试夹具。

## 工序配置紧凑布局（v55）

电脑端按序号、工序、操作要求、人员、参考产能、口径及排序/移除操作排列为一行；表头集中说明，包装要求独立放在列表后。手机每道默认第一行显示序号、工序名称、设置与排序/移除，第二行全宽显示操作要求；人员、参考产能及口径从“设置”展开为完整输入区，不把电脑列挤在窄屏里。长操作要求可展开查看编辑。已下达路线可展开读取设置，但输入仍只读。已有配置的字段、路线版本与报工锁定口径不变；排序/增删往返保留未保存的完整操作要求和包装文本。隔离Chromium验证常态桌面每道43px、320/390/736宽度无横向溢出及已下达只读展开；真实iOS待用户试跑。资源统一为v55，保留HTML网络优先及浏览器业务数据。
